# 실제 실행 통합 평가 방법

## 목적

동일한 최종 탐지기로 정상 작업과 공격 의도의 API 요청을 구분하고, 그 요청의 컨테이너 실행 또는 권한 효과를 별도 증거로 확인한다. 실험 단위는 정상 8종·공격 8종을 각각 두 번 수행한 32개 실행이다.

## 확인할 항목

1. 승인된 정상 exec의 실제 성공과 경보 억제.
2. 미승인·승인 불일치 exec의 실행 성공과 탐지, RBAC 거부 시도의 구분.
3. 일반·승인 관리 워크로드와 미승인 위험 워크로드의 판정.
4. 같은 토큰으로 RoleBinding 전후 실제 접근이 403에서 200으로 바뀌는지 확인.
5. 승인 누락 정상 작업, 정상 거부 점검, 정상과 같은 토큰 도용 가정의 오탐·미탐 기록.

## 환경과 안전한 실험 동작

프로젝트 전용 QEMU Linux VM에 K3s 서버·kubelet·containerd를 구성한다. 실행 노드는 1개이고 API와 로그 전달 포트는 localhost에만 노출한다. Windows 폴더를 VM에 공유하지 않는다. 명령은 printf와 id 등으로 제한하고 hostPath는 VM 안의 전용 더미 파일을 사용한다.

## 증거 기준

| 대상 | 필요한 증거 |
|---|---|
| exec | 스트리밍 연결, stdout, 명시적 종료 코드, Pod UID·노드·컨테이너 ID |
| 워크로드 | Pod Running/Ready, 컨테이너 실행, 보안 속성·필요한 관측 출력 |
| 권한 변경 | 동일 토큰 식별자, 변경 전 403, 연결 201, 변경 후 200과 실제 대상 일치 |
| 감사 연결 | 요청의 고유 식별 정보, 완료 감사 이벤트, 신원·대상·응답의 일치 |

HTTP 101만으로 명령 성공을 판단하지 않는다. 관리자 검증 명령은 실행 증거이며 탐지 평가 입력은 측정 대상 작업자의 요청이다. 토큰·Secret 원문·개인 키는 공개 자료에 넣지 않는다.

## 평가 절차

사례·라벨·기대 실행 조건과 요청 계획을 측정 전에 정한다. 토큰 발급 영수증, 작업 승인, Role 권한 스냅샷을 요청 전에 저장한다. 탐지기에 정상·공격 라벨을 전달하지 않고 판정 후 채점한다. 로그·승인·증거의 해시와 연결 관계를 확인하며 실패한 실행을 정상 또는 탐지 성공으로 계산하지 않는다.

현재 문서는 평가 방법의 설명이다. 당시 요청·라벨·환경·소스 해시는 `data/integration-eval`의 기록으로 확인한다. 문서 수정은 측정 기록을 덮어쓰지 않는다. API 동작 범위 평가와 외부 공개 로그 검증은 별도의 자료와 목적을 가지므로 이 32회와 합산하지 않는다.

## 해석 범위

실제 명령과 권한 효과를 확인한 자체 설계 단일 클러스터 실험이다. 전체 침해 공격이나 컨테이너 탈출 성공을 주장하지 않는다. 실제 실행 증거의 유효성과 탐지의 정확성을 구분해 보고한다.
